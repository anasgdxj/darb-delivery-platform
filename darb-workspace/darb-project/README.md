# دَرْب | DARB

منصة توصيل متعددة الأدوار: عميل، بائع، سائق، وإدارة.

## محتويات الحزمة

- `backend/`: NestJS + Prisma + PostgreSQL/PostGIS + Redis.
- `mobile/`: مصدر تطبيق Flutter عربي RTL، مع شاشة دخول OTP وربط API وشاشات أساسية حسب الدور.

## ما أُضيف في هذه الجولة

- استخراج مشروع Backend الأصلي إلى ملفات مستقلة قابلة للتطوير.
- وحدات المدن والمتاجر والكتالوج والطلبات والعناوين.
- طلبات انضمام البائع والسائق، مع إبقائها بحالة `PENDING` حتى اعتماد الإدارة.
- إنشاء الطلب مع التحقق من ملكية عنوان العميل، واعتماد المتجر، وتوفر المنتجات، والكمية، والعملة، ورسوم توصيل أساسية من إعداد المدينة.
- تخصيص الطلبات المتاحة للسائقين المعتمدين والمتصلين في مدينتهم، ومنع السائق من المطالبة بطلب سبق تخصيصه.
- تدفق العميل: استعراض المتاجر والمنتجات، سلة مؤقتة داخل الجلسة، إضافة عنوان، وإرسال الطلب بالدفع عند الاستلام.
- تدفق البائع: عرض الطلبات وتحديثها (قبول، تحضير، جاهز)، وإضافة المنتجات.
- تدفق السائق: التبديل بين متصل/غير متصل، عرض الطلبات المتاحة، المطالبة بالطلب، وتحديث حالتي الاستلام والتسليم.
- واجهات Backend إدارية أولية لعرض طلبات انضمام البائعين والسائقين واعتمادها أو رفضها/تعليقها.

## تشغيل Backend محلياً

1. انسخ `backend/.env.example` إلى `backend/.env` وعدّل الأسرار.
2. شغّل PostgreSQL/PostGIS وRedis عبر `docker compose up -d db redis` من مجلد `backend`.
3. نفّذ `npm install` ثم `npx prisma generate`.
4. أنشئ migrations بعد مراجعة مخطط Prisma وملف SQL المكاني، ثم نفّذ `npx prisma migrate deploy`.
5. شغّل `npm run start:dev`.

في وضع التطوير يطبع مزود SMS رمز OTP في سجل الخادم. لا تستخدم ذلك في الإنتاج.

## تشغيل تطبيق Android

يتطلب Flutter SDK وAndroid SDK. من مجلد `mobile`:

```bash
flutter create --platforms=android .
flutter pub get
flutter run --dart-define=API_BASE_URL=https://YOUR_API_HOST/api/v1
flutter build apk --release --dart-define=API_BASE_URL=https://YOUR_API_HOST/api/v1
```

عنوان API الافتراضي `10.0.2.2` مخصص لمحاكي Android عند تشغيل Backend على جهاز التطوير. الهاتف الحقيقي يحتاج عنوان خادم يمكن الوصول إليه عبر الشبكة أو HTTPS.

## ما لم يكتمل بعد — لا تعتبر هذه الحزمة إصدار إنتاج

- لم يُنفّذ بناء APK أو اختبار تثبيت على هاتف؛ بيئة البناء الحالية لا تحتوي Flutter/Android SDK.
- تثبيت مزود SMS سوري فعلي يتطلب اسم المزود، صيغة API، ومفاتيح حساب تعاقدي. الموجود Adapter HTTP عام وليس تكاملاً مثبتاً مع مزود محدد.
- Firebase Cloud Messaging لم يُربط بعد؛ يتطلب مشروع Firebase وملفات إعداد Android.
- الخرائط والتتبع الجغرافي الحي لم يُربطا بعد؛ يتطلبان مزود خرائط ومفتاح API وخدمة تحديث مواقع السائق.
- لوحة الإدارة لاعتماد البائعين والسائقين وإدارة المدن والمناطق والرسوم غير مبنية بعد.
- لا تزال واجهات تقديم طلب الانضمام كبائع/سائق، ولوحة الإدارة، وتعديل/حذف المنتجات، وإدارة عناوين العميل خارج تدفق الطلب بحاجة إلى تنفيذ. سلة الشراء حالياً مؤقتة داخل شاشة المتجر ولا تحفظ بين الجلسات.
- رسوم التوصيل تستخدم `feeBase` للمنطقة كرسوم ثابتة مؤقتة؛ `feePerKm` وحساب المسافة الفعلي غير مطبقين بعد.
- مجلد migrations غير منشأ بعد؛ لذلك `prisma migrate deploy` لن ينشئ قاعدة بيانات جاهزة حتى تُولّد migration أولية وتُراجع. لا تنشر الحاوية الحالية قبل ذلك. حساب الإدارة الأول يجب إنشاؤه يدوياً بإجراء آمن بعد إعداد قاعدة البيانات؛ لا توجد شاشة أو مسار تسجيل مدير عام.
- لم ينجح `npm install` في بيئة التطوير بسبب انتهاء المهلة؛ لم يتم إجراء typecheck أو Nest build أو اختبارات تشغيل. فحص transpile لصياغة 45 ملف TypeScript لم يُظهر أخطاء صياغية فقط، وهذا لا يثبت صحة الأنواع أو التشغيل.
- لم يُرفع المشروع إلى GitHub: أداة GitHub المتصلة لا تنشئ مستودعاً جديداً، ومحاولة إنشاء مستودع خاص عبر المتصفح توقفت لأن جلسة GitHub غير مسجّلة الدخول.
- يلزم مراجعة أمنية، اختبارات تكامل، واختبارات migrations قبل النشر.

## ملاحظات أمنية

- لا تضع مفاتيح SMS أو Firebase أو JWT داخل تطبيق الهاتف.
- استخدم HTTPS في الإنتاج، وغيّر جميع الأسرار الافتراضية.
- لا تفعّل `usesCleartextTraffic` في إصدار الإنتاج.
- أضف صلاحيات الإدارة وآلية اعتماد رسمية قبل فتح التسجيل التجاري.
